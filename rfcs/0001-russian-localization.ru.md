# RFC 0001 — Синхронизированная русская локализация

## Статус

**Принято к реализации в Foundation v0.1.** Владелец проекта одобрил полноценную русскую документацию 3 августа 2026 года. Реализация остаётся предварительной до проверки модели переводов верификатором и завершения миграции.

## Проблема

AXIOPRA проектируется для международного применения, однако её основатель, первый эталонный инженерный проект и значительная часть начальной аудитории работают на русском языке. Только английская нормативная документация создаёт лишний барьер. Но две независимо поддерживаемые нормативные версии создают более опасную проблему: незаметное смысловое расхождение.

Проекту нужна модель, обеспечивающая полную доступность на русском языке и одновременно сохраняющая единый инженерный граф.

## Решение

- Английский остаётся каноническим языком артефактов.
- Русский становится обязательной полноценной локализацией пользовательских материалов.
- Локализованные файлы получают суффикс `.ru.md` рядом с источником.
- Переводы содержат машинно-читаемые метаданные.
- Переводы исключаются из поиска канонических артефактов и не получают дублирующих ID.
- Изменения канона и локализации выполняются в одном pull request либо перевод явно помечается как устаревший.
- Статус `synchronized` присваивается только после человеческого ревью.
- Публичные русскоязычные релизы требуют полного синхронизированного покрытия.

Подробный контракт определён артефактом `AXP-FND-LANGUAGE`.

## Рассмотренные альтернативы

### Только английский

Отклонено, поскольку противоречит миссии доступности для начинающих и практическим потребностям исходной инженерной области.

### Только русский канон

Отклонено для платформенного слоя, поскольку повысило бы барьер международного принятия, вклада и интеграции с существующими инженерными инструментами.

### Два равноправных канонических языка

Отклонено, поскольку независимо редактируемые нормативные тексты неизбежно расходятся. Для разрешения противоречия потребовался бы третий источник авторитета.

### Автоматический перевод при просмотре

Отклонено как единственная модель: результат зависел бы от вендора, был бы невоспроизводим, плохо проверяем и не давал бы устойчивых ссылок и релизных свидетельств.

### Отдельный репозиторий переводов

Отложено. При масштабировании сообщества это может быть полезно, но сейчас добавит лишнюю сложность синхронизации и вклада до стабилизации ядра.

## Последствия

### Положительные

- Русскоязычные пользователи получают полный маршрут работы.
- Сохраняется один канонический смысловой граф.
- Дрейф становится видимым и позднее машинно-проверяемым.
- Любой поставщик LLM может помогать, не владея состоянием перевода.
- Сам перевод становится способом смыслового ревью: неясный исходник должен быть исправлен выше по цепочке.

### Затраты

- Каждое пользовательское изменение требует работы над переводом.
- Релизные ворота становятся строже.
- Нужны рецензенты, понимающие оба языка.
- Справка CLI и диагностики должны получить локализационную архитектуру до публичного alpha-релиза.

### Риски

- Русский файл может выглядеть актуальным, фактически будучи устаревшим.
- Дословный перевод может изменить силу обязательства или технический смысл.
- Участники могут обновлять только понятный им язык.
- Модель может ложно заявить о человеческом ревью.

Эти риски снижаются схемой метаданных, правилом одного изменения, статусом `stale`, обязательным человеческим ревью и будущими проверками верификатора.

## Совместимость

Существующие ID канонических артефактов не меняются. Русский корневой README и русские документы RoadCore остаются действительными. Поиск канонических артефактов исключает `.ru.md`, предотвращая ложные ошибки схемы и дублирование узлов.

## План миграции

1. Добавить схему переводов, шаблон, конфигурацию манифеста и протокол AI-агентов.
2. Перевести основной маршрут чтения: фундамент, метамодель, жизненный цикл, верификацию, исследования, управление и дорожную карту.
3. Перевести подробные контракты проверки и доказательности.
4. Начиная со следующей спецификации, создавать EN- и RU-файлы одновременно.
5. Реализовать проверки локализации в Rust-верификаторе.
6. Достичь полного покрытия `synchronized` до первого публичного русскоязычного alpha-релиза.

## План проверки

- Проверить метаданные переводов по JSON Schema.
- Подтвердить, что поиск канонических артефактов игнорирует `.ru.md`.
- Проверить существование каждого пути и ID источника.
- Сравнить нормативные документы высокого риска человеком.
- Провести тест прохождения новичком, использующим только русские точки входа.
- Добавить положительные и отрицательные фикстуры локализации в набор тестов верификатора.

## Критерии пересмотра

Решение следует пересмотреть, если модель соседних файлов создаёт неуправляемый дрейф, существенно мешает работе участников или препятствует надёжным инструментам. Иная упаковка может быть предложена новым RFC, однако единый смысловой авторитет сохраняется как конституционное требование, пока не изменена сама Конституция.
