# Языковая политика и русская локализация

## Зачем существует эта политика

AXIOPRA предназначена для международного применения, однако её основатель и первая эталонная инженерная область работают преимущественно на русском языке. Русскоязычный пользователь должен понимать весь инженерный путь без необходимости вручную переводить каждый документ. Одновременно две независимо редактируемые нормативные версии неизбежно начнут противоречить друг другу.

Поэтому платформа сочетает языковую доступность с единым смысловым источником истины.

## Основное решение

1. **Английский является каноническим языком артефактов платформы.**
2. **Русский является обязательной полноценной локализацией пользовательской документации платформы.**
3. Русский документ — синхронизированный перевод, а не самостоятельный канонический артефакт.
4. При расхождении версий действует английский канонический артефакт, пока дефект не исправлен.
5. Неоднозначность, обнаруженная при переводе, сначала исправляется в каноническом источнике, после чего перевод обновляется.

Это решение не утверждает культурного или интеллектуального превосходства английского языка. Оно создаёт единый устойчивый смысловой авторитет для глобального машинно-читаемого проекта.

## Соглашение об именах файлов

Для канонического файла:

```text
docs/path/document.md
```

русский перевод располагается по адресу:

```text
docs/path/document.ru.md
```

Для корневых точек входа допускаются установившиеся имена `README.md` и `README.ru.md`.

## Метаданные перевода

Каждый локализованный документ в `docs/` или `rfcs/` начинается с YAML-блока `translation`, проверяемого схемой [`../../schemas/translation.schema.json`](../../schemas/translation.schema.json). Он содержит:

- язык локализации;
- путь к каноническому источнику;
- идентификатор канонического артефакта;
- версию источника;
- статус синхронизации;
- способ перевода;
- сведения о человеческом ревью для синхронизированного перевода.

Файлы переводов исключаются из поиска канонических артефактов. Они не получают самостоятельных ID и не создают дублирующие узлы графа.

## Состояния перевода

- `draft` — перевод неполный или только что создан;
- `review` — перевод готов к лингвистическому и смысловому ревью человеком;
- `synchronized` — перевод проверен и соответствует указанной версии источника;
- `stale` — канонический источник изменился либо известно о расхождении.

Перевод не может получить статус `synchronized` без указанного человека-рецензента и даты проверки.

## Обязательное покрытие

Русская локализация обязательна для:

- пользовательских точек входа;
- руководств по фундаменту, метамодели, методологии, верификации, исследованиям, управлению и дорожной карте;
- шаблонов артефактов, RFC, доказательных досье и проектов;
- учебных материалов для начинающих и описаний эталонных проектов;
- справки CLI и диагностик до первого публичного alpha-релиза для русскоязычных пользователей.

Идентификаторы исходного кода, ID артефактов, имена файлов, команды, ключи JSON/YAML, типы Rust, утверждения Lean и поля протоколов остаются неизменными, пока для них не определён отдельный слой локализации.

## Правило одного изменения

При изменении пользовательского канонического документа тот же pull request обязан выполнить один из вариантов:

1. обновить русский перевод и указать соответствующую версию источника;
2. пометить русский перевод как `stale` и создать блокирующую задачу локализации;
3. документировать, почему данный артефакт освобождён от перевода.

Скрытый дрейф запрещён. Во время текущей pre-alpha-миграции неполное историческое покрытие отслеживается явно и блокирует первый публичный alpha-релиз, но не каждый промежуточный коммит.

## Правила смысловой точности

Перевод обязан сохранять:

- силу обязательств `must`, `must not`, `should`, `may`;
- область действия, предположения, исключения и non-goals;
- метки доказательности и уверенности;
- различие между фактом, выводом, решением, гипотезой и неизвестным;
- ID артефактов, направление связей, ID правил, команды, пути и код;
- предупреждения о том, чего верификатор или доказательство установить не могут.

Перевод может улучшать читаемость для русскоязычного пользователя, но не имеет права добавлять новое требование, обещание, исключение или толкование.

## Требования к AI-агентам

AI-агент обязан:

- прочитать канонический источник перед редактированием перевода;
- при изменении смысла сначала обновить английский канон;
- писать по-русски ясным профессиональным языком, а не выполнять дословную подстановку слов;
- сохранять технические идентификаторы без изменений;
- указывать участие LLM в метаданных перевода;
- не присваивать собственному переводу статус `synchronized` без человеческого ревью;
- сообщать о неоднозначности, а не молча выбирать удобное толкование.

## Планируемые детерминированные проверки

Rust-верификатор позднее будет проверять:

- наличие обязательной пары переводов;
- соответствие метаданных перевода схеме;
- существование пути и ID источника;
- совпадение версии источника;
- появление статуса `stale` после изменения канона;
- полноту покрытия выбранного релизного профиля;
- неработающие ссылки и непереведённые placeholders.

Эти проверки подтверждают структуру синхронизации и покрытие. Они не доказывают лингвистическое или смысловое качество — для этого сохраняются семантический аудит и ревью человеком.

## Релизные ворота

Первый публичный alpha-релиз для русскоязычных пользователей требует:

- полного обязательного RU-покрытия;
- отсутствия обязательных переводов в состояниях `draft`, `review` или `stale`;
- зафиксированного человеческого ревью;
- успешных структурных проверок локализации;
- выборочного смыслового сравнения нормативных документов высокого риска.

## Видимый результат

Русскоязычный начинающий пользователь может пройти от корневого README через фундамент, метамодель, жизненный цикл, верификацию, дорожную карту и примеры, не теряя связь с каноническим источником.

## Критерий готовности

Политика считается реализованной, когда репозиторий содержит единый канонический смысловой граф, русские переводы указывают точные исходные артефакты и версии, дрейф виден, а релиз не может выдать устаревшие локализованные правила за актуальную истину.
